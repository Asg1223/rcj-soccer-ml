# 6-3 画像を集める

## ねらい

- CoreS3 のカメラで、学習用の画像を SD カードに保存できる
- 「どんな画像を、どれくらい、どう撮りためるか」を決められる

---

## 理論：良い学習用画像とは

モデルは、**学習で見たことのある見え方** には強く、見たことのない見え方には弱くなります。だから、本番で起こりうる見え方を、できるだけ全部撮っておきます。

| 変えること | 例 |
|---|---|
| 距離 | ボールが目の前（5 cm）〜コートの反対側 |
| 位置 | 画面の左・真ん中・右、端で半分切れている |
| 照明 | 部室、体育館、窓ぎわ、本番の会場 |
| 隠れ方 | ロボットの後ろに半分隠れたボール |
| ロボット | 自分のチーム、**知り合いのチームのロボット**（6-8） |
| 何もない画像 | ボールもゴールも写っていない画像（「何もない」も大事な答え） |
| 動き | ロボットが動いているときの、ぶれた画像 |

**撮影した日・場所ごとにフォルダを分けて** おくと、2-4 と同じように「取り直しごと」に学習用とテスト用を分けられます（6-4）。

!!! private "撮った画像はチームの情報"
    撮った画像には、自分のロボットの形、会場の様子、知り合いのチームのロボットが写ります。**チーム用リポジトリ（またはドライブ）にだけ** 置きます。他のチームのロボットを撮るときは、必ず許可をもらい、使い道（自分のチームの学習だけに使う、公開しない）を伝えます（6-8）。

---

## 手を動かす 1：撮影用のスケッチを書き込む

1. ライブラリマネージャで **M5CoreS3** を入れます（M5Unified は 0-2 で入れたもの）
2. `firmware/cores3/camera_capture/camera_capture.ino` を開き、ボードを **M5CoreS3** にして書き込みます
3. FAT32 の microSD カードを入れます

| 操作 | 働き |
|---|---|
| 画面をタッチ | 1 枚撮って、`/img/img_00001.jpg` のように保存 |
| 右下をタッチ | AUTO（1 秒に 1 枚、自動で撮る）の入・切 |

画面の上に `SD ok saved:12` のように、保存した枚数が出ます。

!!! tip "ロボットに付けた状態で撮る"
    カメラの高さや向きが変わると、見え方が変わります。**本番と同じように、ロボットに CoreS3 を付けた状態で** 撮りましょう。CoreS3 のカメラは画面の下にあるので、取り付けの向きを決めてから撮り始めます。

## 手を動かす 2：撮り方の計画を立てる

いきなりたくさん撮るより、**少し撮って学習して、苦手な見え方を足していく** ほうが効率的です。

1. まず、いろいろな距離・位置のボールを 200 枚くらい撮る
2. 6-6 の方法で学習して、テスト用の画像で **見のがし・まちがい** を調べる
3. 苦手だった見え方（例：遠いボール、ロボットの後ろのボール）を重点的に撮り足す
4. くり返す

実機がない人は、シミュレータで同じ流れを体験できます。

```python
import numpy as np
from collections import Counter
from rcjml.sim.camera import make_images, CLASSES

X, labels, infos = make_images(1000, seed=1)
count = Counter(CLASSES[b.cls] for boxes in labels for b in boxes)
print("写っている数:", dict(count))
print("ボールが写っていない画像:", sum(not any(b.cls == 0 for b in boxes) for boxes in labels), "枚")

dist = np.array([i["ball"]["distance_cm"] for i in infos if i["ball"]])
print("ボールの距離（cm）の分布:", np.histogram(dist, bins=[0, 20, 40, 80, 160])[0])
```

## 手を動かす 3：PC に移して整理する

SD カードの `/img/` を PC にコピーし、チーム用リポジトリに次のように置きます。

```text
rcj-soccer-ml-team/
└─ data/camera/
   ├─ 2026-11-20_bukatsu/       ← 撮影した日・場所ごと（＝取り直し）
   │  ├─ img_00001.jpg
   │  └─ …
   └─ 2026-12-05_taiikukan/
```

画像が多くなると、リポジトリが重くなります。1 GB を超えそうなら、画像はドライブに置き、リポジトリにはフォルダの場所だけを書いておきます（0-3）。

## チェック問題

1. 学習用の画像に、ボールが写っていない画像も入れるのはなぜですか。
2. 撮影した日・場所ごとにフォルダを分けておくと、何に役立ちますか。

??? note "答え"
    1. 本番では「ボールが見えていない」ときもあるからです。写っていない画像がないと、モデルは何でもボールだと思いこむようになります。
    2. 学習用とテスト用を「撮影した日・場所」で分けられ、初めての会場でうまくいくかを正しく評価できます（2-4 と同じ考え方）。

## つまずきポイント

??? failure "`Camera Init Fail` と出る"
    ボードが **M5CoreS3** になっているか、M5CoreS3 のライブラリが入っているかを確かめます。CoreS3 の種類によっては、カメラが付いていないもの（CoreS3 SE など）もあります。

??? failure "画像が暗い・色がおかしい"
    カメラは起動してすぐは明るさの調整が終わっていません。電源を入れて数秒たってから撮ります。

## もっと深く

!!! deeper "Wi-Fi で PC に送る"
    SD カードの抜き差しが面倒なら、ESP32 の Wi-Fi を使って、ブラウザから CoreS3 のカメラを見たり、画像を保存したりできます（Espressif の `CameraWebServer` の例を CoreS3 用に直したものが公開されています）。ただし、大会の会場では Wi-Fi の使用に決まりがあることが多いので、ルールを必ず確かめます。

# 6-4 ラベルを付ける

## ねらい

- 撮った画像に、「ボール・黄ゴール・青ゴール・ロボット」の 4 種類の **枠（バウンディングボックス）** を付けられる
- ラベルを YOLO 形式で書き出し、ノートブックで読み込める
- 学習用とテスト用を、**撮影した日・場所** で分けられる

---

## 理論 1：何を「正解」として付けるか

物体検出の正解は、「画像のどこに、何があるか」です。物を囲む四角い枠と、その種類の組を、画像ごとに付けます。

| 種類の番号 | 名前 | 付け方 |
|---|---|---|
| 0 | `ball` | ボール全体を囲む。半分隠れていたら、見えている部分を囲む |
| 1 | `yellow_goal` | 黄色いゴールの、見えている部分 |
| 2 | `blue_goal` | 青いゴールの、見えている部分 |
| 3 | `robot` | ロボット全体。自分のチームも相手も「robot」 |

**付け方の決まりを、チームで1つに決めて紙に書いておく** のが大事です。人によって「半分隠れたボールを付けるか」がばらばらだと、モデルが迷います（1-4 の「ラベルのずれ」と同じ話です）。

## 理論 2：YOLO 形式

ラベル付けツールの書き出し方はいろいろありますが、この教材では **YOLO 形式** を使います。画像 1 枚につき、同じ名前の `.txt` ファイルを 1 つ作り、1 行に 1 つの物を書きます。

```text
0 0.531250 0.812500 0.083333 0.083333
3 0.250000 0.552083 0.229167 0.208333
```

左から「種類の番号、枠の中心の x、中心の y、幅、高さ」です。位置と大きさは、画像の幅・高さを 1 とした割合で書きます。

## 理論 3：ツールの選び方

画像はチームの情報なので、**画像をどこかのサーバーに送らないツール** を選びます。

| ツール | 特徴 |
|---|---|
| **makesense.ai**（この教材のおすすめ） | ブラウザで動き、インストールも登録もいらない。画像はブラウザの中だけで扱われ、サーバーに送られない。YOLO 形式で書き出せる |
| VGG Image Annotator（VIA） | 1 つの HTML ファイルで、インターネットなしでも動く |
| Label Studio、CVAT | 自分の PC にサーバーを立てて使う。チームで分担するとき向き |

!!! private "ラベル付けツールの使い方に注意"
    「無料・オンライン」のツールの中には、画像をサーバーに保存したり、無料のかわりに **データを公開** したりするものがあります。使う前に、画像がどこに送られるかを必ず確かめます。Edge Impulse（6-6）を使うときも、プロジェクトは必ず **Private** にします。

## 手を動かす 1：makesense.ai でラベルを付ける

1. ブラウザで [makesense.ai](https://www.makesense.ai/) を開き、「Get Started」を押します
2. 6-3 で撮った画像（1 つの撮影フォルダ分）をドラッグして入れ、「Object Detection」を選びます
3. ラベルの名前を、**この順番で** 作ります：`ball`, `yellow_goal`, `blue_goal`, `robot`
4. 四角を描いて、種類を選びます。全部の画像に付けます（何も写っていない画像は、何も付けずに次へ）
5. 「Actions → Export Annotations」で **YOLO** 形式を選んで書き出します。zip の中の `.txt` を、画像と同じフォルダに入れます

!!! tip "ラベル付けを速くするコツ"
    - 1 回に全部やろうとせず、1 日 100 枚ずつなど区切る
    - 2 人で同じ 20 枚に付けて、付け方がそろっているかを比べる
    - 6-6 で一度学習したら、モデルの予測を「下書き」にして、直すだけにする（予測ラベル付け）

## 手を動かす 2：ノートブックで読み込む

チーム用リポジトリの `data/camera/` に、撮影フォルダごとに画像と `.txt` を置いたら、次のように読みます。

=== "チーム用のデータで"

    ```python
    from pathlib import Path
    from rcjml.vision import load_yolo_folder

    X, labels, sessions = load_yolo_folder(
        Path("~/rcj-soccer-ml-team/data/camera"),          # Colab ならドライブの場所
        class_names=["ball", "yellow_goal", "blue_goal", "robot"],   # ツールで作った順番
    )
    print(X.shape, len(labels), sorted(set(sessions)))
    ```

画像は 96 × 96 に縮めて読み込まれ、枠もそれに合わせて直されます。`sessions` には撮影フォルダの名前が入ります。

実機の画像がない人は、シミュレータの画像を YOLO 形式で書き出して、同じ読み込みを試せます。

```python
import tempfile, pathlib, cv2
from rcjml.sim.camera import make_images, boxes_to_yolo
from rcjml.vision import load_yolo_folder

X, labels, _ = make_images(20, seed=5)
root = pathlib.Path(tempfile.mkdtemp())
for k, (img, boxes) in enumerate(zip(X, labels)):
    session = root / ("day1" if k < 10 else "day2")
    session.mkdir(exist_ok=True)
    cv2.imwrite(str(session / f"img_{k:05d}.png"), cv2.cvtColor(img, cv2.COLOR_RGB2BGR))
    (session / f"img_{k:05d}.txt").write_text(boxes_to_yolo(boxes))

X2, labels2, sessions2 = load_yolo_folder(root)
print(X2.shape, sorted(set(sessions2)))
print(open(next(root.rglob("*.txt"))).read())
```

## 手を動かす 3：撮影した日・場所で分ける

```python
import numpy as np
sessions2 = np.array(sessions2)
test_mask = sessions2 == "day2"              # 最後の撮影をテスト用に
print("学習用", (~test_mask).sum(), "枚、テスト用", test_mask.sum(), "枚")
```

ランダムに分けると、同じ日に続けて撮った「ほぼ同じ画像」が学習用とテスト用の両方に入ってしまいます（2-4）。必ず撮影の単位で分けます。

## チェック問題

1. 画像の幅 96、高さ 96 で、枠が x = 40〜56、y = 70〜86 のボール。YOLO 形式の 1 行はどうなりますか。
2. ラベル付けツールで、種類の順番を `robot, ball, …` と作ってしまいました。どうすればよいですか。
3. チームの 2 人で手分けしてラベルを付けるとき、最初にやっておくことは何ですか。

??? note "答え"
    1. 中心は (48, 78)、幅・高さは 16 なので、`0 0.500000 0.812500 0.166667 0.166667` です。
    2. `load_yolo_folder` の `class_names` に、ツールで作った順番（`["robot", "ball", ...]`）を渡すと、この教材の順番に並べかえて読み込みます。
    3. 付け方の決まり（半分隠れたもの、遠くの小さいもの、画面の端で切れたものをどうするか）を決め、同じ画像に 2 人で付けて比べることです。

## つまずきポイント

??? failure "読み込んだ枠の位置がずれている"
    ツールで書き出すときに、YOLO 以外の形式（VOC XML など）を選んでいないか、画像を回転させて保存していないかを確かめます。

## もっと深く

!!! deeper "全部の画像にラベルを付けなくてもよい方法"
    ラベル付けは時間がかかるので、

    - **能動学習**：モデルが「自信がない」画像だけを人がラベル付けする
    - **半教師あり学習**：ラベルのない画像も、モデル自身の予測を仮の正解にして学習に使う
    - **事前学習**：ほかのたくさんの画像で学んだモデルから始めて、少ない画像で仕上げる（7-1 のファインチューニング）

    といった方法があります。どれも、最後に「テスト用の画像には、人がきちんとラベルを付けておく」ことが前提です。

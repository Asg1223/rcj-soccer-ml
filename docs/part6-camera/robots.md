# 6-8 相手ロボットを見つける

## ねらい

- 「自分のチームのロボットだけ」で学習すると、知らないチームのロボットを見のがすことを確かめる
- 何チーム分のロボットを集めればよいか、データ拡張がどれくらい効くかを数字で比べる
- 知り合いのチームに画像を頼むときの約束事がわかる

---

## 理論：「見たことがない相手」が本番

ボールとゴールは、どの大会でもほぼ同じ見た目です。ところが **相手ロボットは、チームごとに形も色もばらばら** です。しかも大会で当たる相手の多くは、練習で一度も見たことがないチームです。

だから相手ロボットの検出は、**学習に使っていないチームのロボットで評価する** のが大事です。第2部で「取り直し（セッション）で分けて評価する」と学んだのと同じ考え方で、ここでは **チームで分けて評価** します。

シミュレータでは、ロボットの見た目を `style`（番号）で決めています。

- 学習：style 0（自分のチーム）、1〜3（知り合いの 3 チーム）、……
- 評価：style 20〜29（一度も学習に使っていない 10 チーム）

!!! private "画像は非公開"
    知り合いのチームのロボット画像は、**そのチームの許可をもらってから** 使い、非公開リポジトリだけに置きます。公開リポジトリや、だれでも見られる Edge Impulse プロジェクトには置きません。使い終わったら消してほしいと言われたら、すぐに消します。

## 手を動かす 1：評価用の「知らないチーム」の画像

```python
import numpy as np
import keras
from rcjml.sim.camera import make_images
from rcjml.vision import build_fomo, fomo_loss, fomo_detections, grid_targets, evaluate, augment_images

X_val, L_val, _ = make_images(1000, seed=2)
X_unseen, L_unseen, _ = make_images(1000, seed=9, robot_styles=tuple(range(20, 30)))   # 知らない 10 チーム
```

## 手を動かす 2：集め方を変えて比べる

```python
def train_eval(styles, aug=False, seed=11):
    X, L, _ = make_images(6000, seed=seed, robot_styles=styles)
    if aug:
        X = augment_images(X, np.random.default_rng(0))
    keras.utils.set_random_seed(0)
    m = build_fomo()
    m.compile(optimizer=keras.optimizers.Adam(2e-3), loss=fomo_loss())
    m.fit(X, grid_targets(L), validation_data=(X_val, grid_targets(L_val)),
          epochs=25, batch_size=64, verbose=0,
          callbacks=[keras.callbacks.EarlyStopping(patience=5, restore_best_weights=True)])
    r = evaluate([fomo_detections(p, 0.5) for p in m.predict(X_unseen, verbose=0)], L_unseen)
    return r

for name, styles, aug in [("自分のチームだけ", (0,), False),
                          ("自分＋知り合い3チーム", (0, 1, 2, 3), False),
                          ("自分＋知り合い3チーム＋拡張", (0, 1, 2, 3), True),
                          ("8チーム", tuple(range(8)), False)]:
    r = train_eval(styles, aug)
    print(f"{name:16s} ロボット 見つけた {r['robot']['recall']:.0%} 当たった {r['robot']['precision']:.0%}"
          f" ／ ボール 当たった {r['ball']['precision']:.0%}")
```

4 回学習するので、CPU で 5〜6 分かかります。

知らない 10 チームの画像での結果です（「見つけた」＝ 本物のうち見つけた割合、「当たった」＝ 見つけたと言ったうち本物だった割合）。

| 学習に使ったロボット | ロボットを見つけた | ロボットで当たった | ボールで当たった |
|---|---|---|---|
| 自分のチームだけ（1 チーム） | 65% | 85% | **67%** |
| 自分＋知り合い 3 チーム | 66% | 93% | 85% |
| 自分＋知り合い 3 チーム＋データ拡張 | 68% | 95% | 90% |
| 8 チーム | **80%** | 92% | 84% |
| （参考）知っているチームで評価（6-6） | 91% | 93% | 87% |

ここからわかること：

1. **知らないチームのロボットは見のがしやすい**。知っているチームなら 91% 見つけられたのに、知らないチームだと 65% まで下がります。
2. **自分のチームだけだと、ボールの誤検出が増える**。相手のオレンジ色の部品を「ボール」とまちがえて、ボールの「当たった」が 67% まで落ちました。いろいろなロボットを「ロボット」として見せておくと、「オレンジだけどボールではない物」があると学べます。
3. **データ拡張は「当たった」を上げる**。明るさや色合いを変えた画像で、誤検出が減ります。ただし「見つけた」はあまり上がりません。
4. **見つける割合をいちばん上げるのは、チームの数を増やすこと**。4 チームから 8 チームにすると、65% 前後から 80% に上がりました。



## 手を動かす 3：誤検出を減らすもう一つの工夫

見つけたと言う **しきい値** を上げると、「当たった」は上がり、「見つけた」は下がります。

```python
m = build_fomo()
m.compile(optimizer=keras.optimizers.Adam(2e-3), loss=fomo_loss())
X, L, _ = make_images(6000, seed=11, robot_styles=tuple(range(8)))
keras.utils.set_random_seed(0)
m.fit(X, grid_targets(L), validation_data=(X_val, grid_targets(L_val)), epochs=25, batch_size=64, verbose=0,
      callbacks=[keras.callbacks.EarlyStopping(patience=5, restore_best_weights=True)])
P = m.predict(X_unseen, verbose=0)
for th in [0.3, 0.5, 0.7, 0.9]:
    r = evaluate([fomo_detections(p, th) for p in P], L_unseen)["robot"]
    print(f"しきい値 {th}: 見つけた {r['recall']:.0%}  当たった {r['precision']:.0%}")
```

| しきい値 | ロボットを見つけた | ロボットで当たった |
|---|---|---|
| 0.3 | 80% | 93% |
| 0.5 | 80% | 93% |
| 0.7 | 76% | 95% |
| 0.9 | 65% | **99%** |

相手ロボットを **よける** ために使うなら、見のがしは困るので、しきい値は低め。相手ロボットの位置から **ゴールのすき間をねらう** なら、誤検出が困るので、しきい値は高め。使い道で決めます。

さらに、1 枚だけでなく **数枚続けて見つかったら本物とする** と、一瞬の誤検出を消せます（第7部 7-4 の追跡）。

## チェック問題

1. 相手ロボットの検出を、学習に使ったチームの画像で評価すると、どんな問題がありますか。
2. 自分のチームのロボットだけで学習すると、ボールの誤検出が増えたのはなぜですか。
3. 画像を集める時間が限られているとき、「1 チームを 1,000 枚」と「10 チームを 100 枚ずつ」のどちらを選びますか。

??? note "答え"
    1. 本番（知らないチーム）より、ずっと良い数字が出てしまいます。本当の実力は、使っていないチームで評価しないとわかりません。
    2. オレンジ色の部品を持つロボットを「ロボット」として見たことがないので、オレンジ色ならボールだと覚えてしまったからです。
    3. 10 チームを 100 枚ずつです。見た目の種類が多いほうが、知らないチームにも強くなります。

## つまずきポイント

??? failure "自分のロボットを「相手」と検出してしまう"
    カメラに自分のロボットの一部（キャッチャーなど）が映り込んでいるかもしれません。映り込む部分を最初から切り取る（6-7）か、その位置の検出を無視します。味方ロボットは「ロボット」として検出されますが、試合では敵か味方か区別しにくいので、まず「よけるべき物」として使うのが簡単です。

??? failure "知り合いのチームに頼みにくい"
    「何に使うか」「どこに置くか（非公開）」「いつ消すか」を最初に伝えると、頼みやすくなります。こちらからも自分のチームの画像を渡す（交換する）と、おたがいの役に立ちます。

## もっと深く

!!! deeper "ドメイン汎化と、オープンセットの問題"
    学習に使っていない「チーム」でも性能が落ちないようにすることを、機械学習では **ドメイン汎化**（domain generalization）と呼びます。チームの数を増やす、強いデータ拡張（色をランダムに大きく変える、形をゆがめる）、学習済みの大きなモデルの特徴を使う（転移学習）などが代表的な方法です。
    また、本番では「ロボットでもボールでもゴールでもない物」（人の手、カメラ、ケーブル）も映ります。学習していない物が来たときに自信を持ってまちがえない工夫は、**オープンセット認識** として研究されています。7-2 の「ボールがないときの信頼度」と同じ問題です。

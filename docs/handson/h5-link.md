# H5 2台をつなぐ：センサ側 → CoreS3

| 時間の目安 | 本文 | 使う機材 |
|---|---|---|
| 90 分 | [5-1](../part5-two-boards/design.md)、[5-2](../part5-two-boards/packet.md)、[5-3](../part5-two-boards/display.md) | PC、センサ側マイコン、CoreS3、ジャンパー線、（5 V のマイコンなら）分圧抵抗かレベル変換 |

## ゴール

- センサ側マイコンから CoreS3 へ、**パケット** でセンサの値を送る
- CoreS3 が BallNet で推定して、画面にボールの方向を表示する
- 通信が **取りこぼしなく・こわれずに** 届いていることを数字で確かめる

---

## ステップ

### 1. CoreS3 だけで試す（25 分）

- [ ] `firmware/cores3/ball_display` をチーム用リポジトリにコピーし、H4 と同じように `export_to_sketch(model, team / "firmware" / "ball_display")` で書き出した
- [ ] ボードを **M5CoreS3** にして書き込んだ
- [ ] CoreS3 を USB でつないだまま、PC からシミュレータの値を送った

```bash
python -m rcjml.packet send-sim --port COM5      # CoreS3 のポート
```

- [ ] 画面の矢印がゆっくり回った
- [ ] `--angle 90 --distance 20` を送ったとき、矢印が **画面の左** を向いた（左が +90°）

!!! note "シミュレータの値と自分のモデル"
    `send-sim` は、例の設定（12 個のセンサ）のシミュレータの値を送ります。自分の機体のセンサの数が違うときは、この段階では矢印がおかしくても気にしません。次の実機の段階で確かめます。

### 2. 配線する（20 分）

5-1 の表のとおりにつなぎます。

- [ ] **GND どうし** をつないだ
- [ ] センサ側の TX → CoreS3 の Port C の RX（G18）につないだ
- [ ] センサ側が **5 V**（Arduino Uno など）のときは、分圧抵抗（1 kΩ と 2 kΩ）かレベル変換を **間に入れた**。テスターで、CoreS3 側が 3.3 V 前後になっていることを確かめた
- [ ] 配線の写真を撮って、記録シートに残した（チーム用リポジトリだけ）

### 3. センサ側から送る（25 分）

- [ ] `firmware/sensor-arduino/ir_ring_uart` に共通のヘッダをコピーした

```bash
python -m rcjml.export headers firmware/sensor-arduino/ir_ring_uart
```

- [ ] 設定部分を H1 と同じにして書き込んだ（Uno は 0・1 番ピンを USB と共用しているので、**書き込むときは配線を外す**）
- [ ] ボールをロボットの周りで動かし、CoreS3 の矢印がついてきた
- [ ] ボールを左（+90°）に置いて、矢印が左を向いた

### 4. 通信の調子を測る（20 分）

画面の右下の `fps`・`ok`・`crc` を使います。

- [ ] 1 分間そのままにして、`ok` と `crc` の増え方を記録した
- [ ] 線を 30 cm くらいに延ばす、手で線を揺らす、などをして `crc` が増えないか確かめた
- [ ] センサ側の電源を抜いたとき、`fps` が 0 になり `ok` が増えなくなるのを確かめた

---

## 合格条件

- [ ] センサ側 → CoreS3 で、矢印がボールの方向を向く（8 方向で確かめる）
- [ ] `fps` が **80 以上**
- [ ] 1 分間で、`crc`（こわれたパケット）が `ok` の **0.1% 以下**
- [ ] 5 V のマイコンを使うとき、CoreS3 の RX に 5 V がかかっていない（テスターで確認済み）

## 困ったとき

??? failure "`ok` が 0 のまま"
    TX と RX が逆かもしれません。`ball_display` の `PORTC_RX`、`PORTC_TX` を入れかえます。GND をつないでいるかも確かめます。通信の速さ（`LINK_BAUD`）が両方で同じか見ます。

??? failure "`crc` がどんどん増える"
    GND が細い・長い、線がモータの線の近くを通っている、速さが高すぎる、が多い原因です。線を短くより合わせる、速さを 57600 bps に下げる、を試します（5-2）。

??? failure "`fps` が低い"
    センサ側で、送る前に `Serial.print` でデバッグ表示をたくさんしていないか見ます。USB の表示は時間がかかります。

## 発展課題

- センサ側で BallNet を動かす（`ir_ring_uart` の `#define RUN_BALLNET`）と、CoreS3 で動かすのとで、`fps` を比べる
- パケットの `SEQ`（通し番号）を使って、何個取りこぼしたかを数える表示を足す（5-2）

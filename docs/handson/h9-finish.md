### 4. 推定の揺れをおさえる（20 分）

- [ ] 7-4 の α-β フィルタを、CoreS3 のスケッチに足した

```cpp
// α-β フィルタ（7-4 の Python 版と同じ）
struct AlphaBeta {
  float x = NAN, v = 0, alpha = 0.5f, beta = 0.1f, gate = 40.0f;
  int miss = 0;
  static float wrap(float a) { while (a > 180) a -= 360; while (a < -180) a += 360; return a; }
  float update(float z, bool ok, float dt) {
    if (isnan(x)) { if (ok) x = z; return x; }
    float pred = wrap(x + v * dt);
    if (ok && fabsf(wrap(z - pred)) < gate) {
      float r = wrap(z - pred);
      x = wrap(pred + alpha * r); v += beta * r / dt; miss = 0;
    } else {
      x = pred; v *= 0.9f;
      if (ok && ++miss > 3) { x = z; v = 0; miss = 0; }   // 本当に動いたらリセット
    }
    return x;
  }
};
AlphaBeta tracker;
uint32_t lastTrackMs = 0;

// loop() の中、rcjml_decode_ball(...) のすぐ後に足す
uint32_t now = millis();
float dt = lastTrackMs ? fmaxf((now - lastTrackMs) / 1000.0f, 0.001f) : 0.01f;
lastTrackMs = now;
ball.angle_deg = tracker.update(ball.angle_deg, ball.confidence > CONF_TH, dt);
```

## 困ったとき

??? failure "追加学習しても、ほとんど良くならない"
    会場のデータの角度・距離が偏っていないか見ます。また、「別の会場」の変化が、センサの値の範囲を超えている（いつも最大値になっている）と、学習ではどうにもなりません。センサの覆いや、測定の設定を見直します。

??? failure "30 分に間に合わない"
    いちばん時間がかかるのは、たいていデータ集めです。CoreS3 のデータ収集モード（5-4）を使う、集める場所を 100 か所に減らす、2 人で分担する（1 人が置いて、1 人が記録）を試します。学習と書き出しは、1 つのノートブックの「上から全部実行」でできるようにしておきます。

??? failure "止まるようにしたら、遠いボールで止まってしまう"
    しきい値が高すぎます。7-2 のとおり、自信が低くなるのは遠いボールが多いです。しきい値を下げるか、「止まる」の代わりに「最後に見えた方向へゆっくり進む」にします。

## 発展課題

- H8 のカメラの角度を使って、6-9 の方法で IR と融合する。前のボールに近づくときの、まっすぐさを比べる
- 7-4 のゴールの柱からの位置推定を使って、ボールが見えないときに自分のゴールの前に戻る動きを作る
- 大会の日の手順書（持ち物、時間、だれが何をするか）を作って、チーム用リポジトリに置く

# 1-4 正解ラベルをつける

## ねらい

- 機械学習に必要な「問題」と「正解」の組を、まちがいなく集められる
- **取り直し（session）** を記録する理由がわかり、条件を変えながら集められる

---

## 理論 1：機械学習は「問題と正解の組」から学ぶ

この教材で作るモデルは、

- **問題**（入力）：センサの値 `s0, s1, …`
- **正解**（ラベル）：そのときのボールの角度・距離・保持しているか

の組をたくさん見て、「この値ならボールはここ」という対応を学びます。このやり方を **教師あり学習** といいます。

だから、**正解がまちがっていると、モデルはまちがいを学びます**。ラベルづけは地味ですが、いちばん大事な作業です。

## 理論 2：角度と距離の決まりごと

| 項目 | 決まりごと |
|---|---|
| 角度 | ロボットを真上から見て、正面が 0°、**反時計回り（左回り）が ＋**。-180°〜180° で書く |
| 距離 | **ロボットの中心からボールの中心まで**（cm） |
| 保持 | キャッチャーにボールが入っている状態を `has_ball = 1` |

## 理論 3：取り直し（session）とは

**取り直し** は「ひとまとまりで集めたデータ」の番号です。たとえば、

- 月曜の放課後に部室で集めた分 → session 1
- 水曜に体育館で集めた分 → session 2
- ボールの電池を替えた後に集めた分 → session 3

のように、**条件が変わったら番号を変えます**。

なぜ記録するのかは第2部（2-4）でくわしく扱いますが、ひとことで言うと「**本番で初めて見る条件でもうまくいくか**」を確かめるためです。同じ取り直しのデータは似ているので、それで練習して同じ取り直しでテストすると、実力より良い点が出てしまいます。

!!! tip "取り直しごとに変えるとよい条件"
    - 場所（部室、教室、体育館、本番に近いコート）
    - 照明（昼・夜、窓のカーテンの開け閉め）
    - ボールの電池（新品・使いかけ）、ボールの個体（大会のボールは1つではない）
    - 周りの物（壁の近く、ほかのロボットがいる・いない）

---

## 手を動かす 1：角度と距離の目印を作る

床に「ボールを置く場所」の目印を作ります。どれか1つで構いません。

=== "紙で作る（おすすめ）"

    1. 大きめの紙（模造紙など）の真ん中に、ロボットを置く位置を描きます
    2. 中心からひもとペンでコンパスのように円を描きます（10, 20, 30, 45, 60, 80, 100, 130 cm）
    3. 分度器で 15° ごとに線を引きます。**正面を 0°** にして、左回りに +15, +30, …、右回りに -15, -30, … と書きます
    4. ロボットの中心と向きを、紙の中心と 0° の線に合わせて置きます

=== "テープで作る"

    床にマスキングテープで十字（0°・90°・180°・-90°）を貼り、メジャーで距離をはかって印を付けます。角度の細かい印は、分度器を印刷した紙を中心に置いて合わせます。

=== "回転台で自動化（発展）"

    ボールの位置は固定して、**ロボットのほうをサーボモータの台で回す** と、角度は自動で変えられます。ボールの角度は「台の角度のマイナス」になります。距離だけ人が変えればよいので、たくさん集めるときに楽です。

## 手を動かす 2：集める順番を決める

教材のロガーの `plan` は、ボールを置く位置を **毎回ちがう順番** で案内してくれます。まず、どんな計画になるかを Python で見てみます。

```python
from rcjml.logger import make_plan

plan = make_plan(seed=1)
print("か所の数:", len(plan))
for spot in plan[:8]:
    print(spot)

samples = 20                 # 1か所で記録する回数
seconds_per_spot = 15        # ボールを置きかえる時間の目安
print(f"1回の取り直し：{len(plan) * samples} 行、だいたい {len(plan) * seconds_per_spot / 60:.0f} 分")
```

角度 24 通り × 距離 8 通り ＋ 保持 3 回で、195 か所です。1か所 15 秒なら、1回の取り直しで 50 分くらいかかります。最初は `--limit 30` などで短くして、慣れてから全部やりましょう。

!!! question "なぜ順番をばらばらにするの？"
    「近い順」に集めると、途中でボールの電池が減ったり、外が暗くなったりしたとき、その変化が **距離と一緒に** データに入ってしまいます。モデルが「暗い＝遠い」と、まちがった関係を覚えるかもしれません。順番をばらばらにすると、こうした変化が特定の位置に偏らなくなります。

## 手を動かす 3：集める

=== "実機"

    ```bash
    python -m rcjml.logger plan --session 1
    ```

    画面の指示（例：`角度 +45°、距離 30 cm に置いて Enter`）に従ってボールを置き、Enter を押します。

    - `s` + Enter：その位置を飛ばす
    - `q` + Enter：途中で終わる（それまでの分は保存されている）

=== "シミュレータ"

    ```bash
    python -m rcjml.logger plan --session 1 --port sim --allow-public --limit 30
    ```

    シミュレータが自動でボールを置くので、Enter を押さなくても進みます。保存先は `data/practice/ir_log.csv` です。

2回目の取り直しは、条件を変えてから `--session 2` で同じことをします。データは同じファイルに追記されます。

!!! warning "集めるときに気をつけること"
    - ボールが **転がっていない** ことを確かめてから Enter を押す
    - ボールの近くに **手や体を入れない**（光をさえぎったり、反射したりする）
    - 記録中に **ロボットを動かさない**
    - 番号をまちがえたら、その取り直しの行を CSV から消して、集め直す

## チェック問題

1. ボールを 30° に置いたのに、`--angle -30` で記録してしまいました。モデルにどんな影響がありますか。
2. 同じ部屋・同じ日に、午前と午後で集めました。取り直しの番号は分けたほうがよいですか。
3. 1回の取り直しで 195 か所 × 20 回を集めると、何行のデータになりますか。

??? note "答え"
    1. 「左にあるボールの値」に「右」という正解が付いたデータが混ざり、モデルが左右をまちがえやすくなります。数が少なくても、大きくまちがった正解は悪い影響が大きいです。
    2. 分けたほうがよいです。窓からの光（外乱光）が変わっているかもしれません。番号を分けておけば、あとでまとめることもできます。
    3. 3,900 行です。

## つまずきポイント

??? failure "途中で止まってしまった"
    `q` で終わった場合も、エラーで止まった場合も、それまでに記録した分は保存されています。もう一度 `plan` を同じ `--session` で実行すると、最初から案内されるので、終わった位置は `s` で飛ばします。

??? failure "保存先が違う場所になっている"
    `python -m rcjml.logger record ...` を実行すると、最後に保存先が表示されます。チーム用リポジトリの `data/ir/` になっていなければ、環境変数 `RCJML_CONFIG` と設定ファイルの `data.dir` を確かめます。

## もっと深く

!!! deeper "ラベルの「ずれ」はどこまで許されるか"
    角度の目印が 2° ずれていても、モデルの誤差が 2° 増えるだけ……とは限りません。ずれ方が **いつも同じ向き**（たとえば紙の置き方がいつも 3° 右に回っている）だと、モデルはそのずれごと覚えてしまい、本番でいつも 3° ずれた答えを出します。**ばらばらのずれ** なら、たくさん集めると平均されて目立たなくなります。
    データを集めるときは、「ずれをなくす」ことと、「ずれが一方に偏らないようにする」ことの両方を意識しましょう。統計では、前者を **系統誤差**、後者を **偶然誤差** と呼びます。

# 4-3 量子化：重みを int8 にして小さくする

## ねらい

- **量子化**（小数を、少ないビット数の整数で表すこと）の仕組みがわかる
- 重みを int8 にして、モデルを約 1/4 にできる
- 量子化で成績がどれくらい変わるかを測れる

---

## 理論 1：重みは「だいたい」でよい

float（32 bit の小数）は、とても細かい数まで表せます。でも、ニューラルネットの重みは、そこまで細かくなくても答えはほとんど変わりません。

そこで、重みを **-127〜127 の整数（int8、8 bit）** で表します。層ごとに1つ、**倍率（scale）** を決めておき、

$$
\text{重み} \approx \text{整数} \times \text{scale}
$$

とします。scale は「その層でいちばん大きい重みの絶対値 ÷ 127」にします。

| 元の重み | ÷ scale（例：0.01） | 四捨五入（int8） | 戻すと |
|---|---|---|---|
| 0.4237 | 42.37 | 42 | 0.42 |
| -1.2701 | -127.01 | -127 | -1.27 |
| 0.0031 | 0.31 | 0 | 0.00 |

1 個 4 バイトだった重みが 1 バイトになるので、**大きさは約 1/4** です。

## 理論 2：量子化の2つのやり方

| やり方 | 中身 | この教材 |
|---|---|---|
| **重みだけ int8** | 重みを int8 で保存し、計算するときに scale をかけて小数に戻す | `rcjml_mlp.h`（このページ） |
| **全部 int8** | 入力・途中の値・重みを全部 int8 にして、整数だけで計算する | TensorFlow Lite Micro（4-4） |

重みだけ int8 は、作り方が簡単で、**フラッシュが小さいマイコン（Uno）** で効きます。全部 int8 は、途中の値の範囲も測っておく必要がありますが、**計算も速く** なります。

## 手を動かす 1：自分で量子化してみる

```python
from rcjml.export import quantize, dequantize

W = layers[0].W                       # 1 層目の重み（12 × 64）
q, scale = quantize(W)
print("scale:", scale)
print("元の重み  :", W[0, :5].round(4))
print("int8      :", q[0, :5])
print("戻した重み:", dequantize(q, scale)[0, :5].round(4))
print("いちばん大きいずれ:", np.abs(W - dequantize(q, scale)).max())
```

ずれは、いちばん大きくても scale の半分（四捨五入の分）です。

## 手を動かす 2：成績がどう変わるか

```python
P_float = forward(layers, X_test)
P_int8 = forward(layers, X_test, quantized=True)

for name, P in [("float", P_float), ("int8 weights", P_int8)]:
    r = evaluate(P, test)
    print(f"{name:13s} 角度 {r['angle_MAE']:.2f}°  距離 {r['dist_rel_median']:.3f}  保持 {r['hold_acc']:.4f}")

n_w = sum(L.W.size for L in layers)
n_b = sum(L.b.size for L in layers)
print(f"重みの大きさ: float {(n_w + n_b) * 4} バイト → int8 {n_w + n_b * 4} バイト")
```

| 重み | 角度 | 距離（割合の真ん中） | 保持の正解率 | 大きさ |
|---|---|---|---|---|
| float | 5.77° | 14.8% | 99.5% | 21,008 バイト |
| int8 | 6.12° | 14.8% | 99.5% | 5,648 バイト |

角度が 0.35° 悪くなるだけで、大きさは約 1/4 になりました（バイアスは小さいので float のまま残しています）。

## 手を動かす 3：int8 のヘッダを書き出す

```python
from rcjml.config import PACKAGE_ROOT
from rcjml.export import export_to_sketch
export_to_sketch(model, PACKAGE_ROOT / "firmware" / "sensor-arduino" / "ballnet_infer",
                 quantized=True, allow_public=True)
```

スケッチはそのまま使えます。`rcjml_mlp.h` は、重みが int8 かどうかを自動で見分けて計算します。教材で gcc を使って確かめたところ、C の答えは NumPy の int8 版と 0.000006 以内で一致しました。

## チェック問題

1. 重みの中でいちばん大きい絶対値が 2.54 の層では、scale はいくつになりますか。
2. その層の重み 0.013 は、int8 ではいくつになりますか。
3. 量子化で成績が大きく落ちたとき、考えられる原因は何でしょう。

??? note "答え"
    1. 2.54 ÷ 127 = 0.02 です。
    2. 0.013 ÷ 0.02 = 0.65 → 四捨五入して 1 です（戻すと 0.02）。
    3. ある層に、ほかよりとても大きい重みが少しだけあると、scale が大きくなり、ほかの小さな重みがみんな 0 や ±1 になってしまいます。層ごとではなく、**出力のニューロンごと** に scale を決めると改善することがあります。

## もっと深く

!!! deeper "量子化を考えて学習する"
    ここでやったのは、学習が終わってから量子化する **学習後量子化** です。成績の落ち方が大きいときは、学習の途中から「量子化したらこうなる」という計算を混ぜて学習する **量子化を考慮した学習**（QAT）という方法もあります。
    また、全部 int8 にするときは、途中の値（ReLU の出力など）の範囲を、学習用データの一部を流して測っておきます。この「範囲を測るためのデータ」を **代表データセット**（representative dataset）といい、4-4 で使います。
